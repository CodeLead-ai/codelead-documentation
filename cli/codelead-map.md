# codelead map

**Applies to:** CodeLead 0.1 and later

`codelead map` reads the repository into its map: the stack, the validation commands, the modules and the entry points. It calls no model. The map is kept in `docs/codelead/repository-map.md` and `.json`.

## Name

`codelead map` - Reads the repository into its map.

## Synopsis

```console
codelead map [--json] [--refresh]
codelead map -h|--help
```

## Description

The [repository map](../concepts/repository-map.md) is CodeLead's summary of a repository. Other commands use it: the [preflight](codelead-preflight.md) adds it to the model's context, and the chat reads it to answer questions. [`codelead init`](codelead-init.md) writes the first map.

The map has two files:

- `docs/codelead/repository-map.md`, for people: the stack, the validation commands, the modules, the entry points, what the System Model has read, and the stamp.
- `docs/codelead/repository-map.json`, for programs: the same, with the files of each module.

> [!NOTE]
> **New to this?** CodeLead writes the map from the code, not with a model. The same code always gives the same map. Commit it with the code. Do not edit it by hand: the next read writes it again.

### Fresh or stale

The map carries a **stamp**: the git head, whether there were uncommitted changes, and the number of files. The map is **fresh** while the git head is the same and the file count moves by 2% or less. Then `codelead map` uses it as it is. The map is **stale** when the head moves, or when the count moves by more than 2%. CodeLead then reads the repository again, and the first line says why.

`--refresh` reads the repository again, fresh or not.

### The knowledge base

Each map that is written seeds the [knowledge base](../concepts/knowledge-base.md): the stack, the validation commands and the modules become entries with their evidence. One [evidence record](../concepts/evidence-records.md) keeps the read. A fresh map that is only used adds nothing.

> [!TIP]
> **For experienced users:** `--json` prints the map itself (`codelead.repository-map/1`) with `stamp.head`, `stamp.dirty`, `stamp.fileCount`, `stamp.libraryHash` and `stamp.filesHash`. The knowledge base is seeded the same way with `--json`.

## Options

- **`--json`**

  Prints the map as JSON. The default is a summary of three or four lines.

- **`--refresh`**

  Reads the repository again, even when the kept map is fresh.

## Examples

- Read the map of the Basic Store sample, when the kept map is fresh:

  ```console
  codelead map
  ```

  ```output
  Repository map is fresh: 1 module, 89 files; docs/codelead/repository-map.md
  Entry points: WebApplication1/webapp.csproj
  Stamp: git c5a5ce8920b8 (uncommitted changes), 89 files scanned, written 2026-11-20T04:10:50.540Z
  ```

- After a commit, the map is stale. CodeLead says why, and writes it again:

  ```console
  git commit -m "CodeLead initialized"
  codelead map
  ```

  ```output
  Repository map was stale: the git head moved from c5a5ce8920b8 to 1e12fa703703. Rewritten: 1 module, 89 files; docs/codelead/repository-map.md
  Entry points: WebApplication1/webapp.csproj
  Stamp: git 1e12fa703703, 89 files scanned, written 2026-11-20T04:13:23.803Z
  Encyclopedia: 4 entries from the map (0 new, 4 updated, 0 downgraded); evidence record ev-20261120041323-r9uod8.
  ```

- Read the repository again, fresh or not:

  ```console
  codelead map --refresh
  ```

  ```output
  Repository map read again (--refresh): 1 module, 89 files; docs/codelead/repository-map.md
  Entry points: WebApplication1/webapp.csproj
  Stamp: git 1e12fa703703, 89 files scanned, written 2026-11-20T04:13:24.763Z
  Encyclopedia: 4 entries from the map (0 new, 4 updated, 0 downgraded); evidence record ev-20261120041324-5jdn61.
  ```

- The start of `docs/codelead/repository-map.md`:

  ```output
  # Repository map

  <!-- Generated by CodeLead (codelead map) from the code, with no model call. Rewritten by codelead map --refresh; not edited by hand. -->

  **Stack:** C#, JavaScript; tools: .NET; an existing project

  ## Validation commands

  - `dotnet build`

  ## Modules

  1 module, 89 files. The files of each module are listed in `repository-map.json`.
  …
  ```

  This project declares no validation commands. A project that declares them in `.codelead/validation.json` sees them first, each marked `(declared in .codelead/validation.json)`. The JSON file then also holds them in `declaredValidationCommands`. See [The repository map](../concepts/repository-map.md).

- Print the map as JSON:

  ```console
  codelead map --json
  ```

  ```output
  {
    "schema": "codelead.repository-map/1",
    "writtenAt": "2026-11-20T04:13:24.763Z",
    "stamp": {
      "head": "1e12fa7037031f024f9d61ae57c3303d4c45194e",
      "dirty": false,
      "fileCount": 89,
  …
  ```

## Exit codes

| Code | Meaning |
|---|---|
| `0` | The map is there: fresh, or written. A knowledge base that could not be seeded is one line, not a failure. |
| `1` | The map could not be read or written. |

## Files

| File | What `map` does with it |
|---|---|
| `docs/codelead/repository-map.md`, `.json` | Reads the stamp. Writes the map when it is stale, or with `--refresh`. |
| `docs/codelead/CATALOG.md`, `catalog.json` | Registers the map. |
| `.codelead/validation.json` | Reads the declared validation commands, which the map lists first. |
| `.codelead/knowledge.json` | Adds or updates the entries of a written map. |
| `.codelead/evidence/ev-*.json` | Writes one record for each written map. |
